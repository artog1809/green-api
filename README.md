# MAX Chat — интерфейс для GREEN-API

Веб-интерфейс для переписки в мессенджере **MAX** через [GREEN-API](https://green-api.com/max).
Пользователь входит с учётными данными инстанса, открывает чат по номеру
телефона, отправляет текстовые сообщения и видит ответы собеседника.

Прототип интерфейса — [web.max.ru](https://web.max.ru/): слева список чатов с
полем для номера, справа переписка и поле ввода.

## Стек

React 19 · TypeScript · Vite · Zustand · TanStack Query · CSS Modules · Vitest + Testing Library

## Быстрый старт

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:5173`.

## Настройка инстанса GREEN-API

Перед первым входом инстанс нужно подготовить — иначе очередь уведомлений будет
пустой и входящие сообщения не появятся:

1. Создайте инстанс для MAX в [личном кабинете](https://console.green-api.com/) и привяжите аккаунт.
2. В настройках инстанса:
   - `Адрес отправки уведомлений (URL)` — **оставьте пустым**, иначе уведомления
     уйдут на webhook, а не в очередь;
   - `Получать уведомления о входящих сообщениях и файлах` (`incomingWebhook`) — «Да»;
   - `Получать уведомления о сообщениях, отправленных с API` — «Да», по ним
     приложение узнаёт настоящий `chatId` собеседника;
   - `Получать уведомления о статусах отправленных сообщений` — «Да», для
     галочек «доставлено / прочитано».

   Если этого не сделать, приложение не будет молча висеть: оно проверяет
   настройки методом `getSettings` и показывает баннер с кнопкой «Включить»,
   которая выставляет всё перечисленное через `setSettings`. После смены
   настроек инстанс перезапускается — до пяти минут.
3. Скопируйте `idInstance` и `apiTokenInstance` — их вводят на экране входа.

Если адрес API вашего инстанса отличается от `https://api.green-api.com`, его
можно указать прямо в форме входа или задать через `.env` (см. `.env.example`).

## Как пользоваться

1. Введите `idInstance` и `apiTokenInstance` — приложение проверит их методом
   `getStateInstance` и не пустит дальше, пока инстанс не авторизован.
2. Введите номер телефона получателя в поле слева и нажмите «+» — появится чат.
3. Напишите сообщение и отправьте (`Enter` — отправить, `Shift+Enter` — перенос строки).
4. Ответ собеседника появится в чате автоматически, без перезагрузки страницы.
5. Чатов может быть несколько: сообщение в неоткрытый чат тоже дойдёт — он
   поднимется наверх списка и покажет счётчик непрочитанных. Сообщение с
   незнакомого номера заводит новый чат.

## Архитектура

Проект собран по [Feature-Sliced Design](https://feature-sliced.design/): слои
импортируют только те, что лежат ниже, каждый слайс отдаёт наружу публичный API
через `index.ts`.

```
src/
  app/        провайдеры (QueryClient, ErrorBoundary), роутинг
  pages/      login, chat
  widgets/    chat-list (панель с полем номера), chat-window (переписка)
  features/   auth, open-chat, send-message, receive-messages
  entities/   session (учётные данные), chat (список чатов), message (модель и история)
  shared/     api/green-api, lib (телефон, дата), ui (кнопки, поля), styles, config
```

### Используемые методы GREEN-API

| Метод | Где | Зачем |
|---|---|---|
| `getStateInstance` | `features/auth` | проверка учётных данных при входе |
| `getSettings` / `setSettings` | `features/receive-messages` | проверка и починка настроек уведомлений |
| `sendMessage` | `features/send-message` | отправка текста |
| `receiveNotification` / `deleteNotification` | `features/receive-messages` | получение входящих |
| `getChatHistory` | `entities/message` | история переписки при открытии чата |

## Принятые решения

**Получение сообщений — цикл опроса очереди.** Запрос `receiveNotification`
с `receiveTimeout=20` → обработка → `deleteNotification` → следующий запрос.
Без `deleteNotification` очередь встаёт и новые сообщения не приходят, поэтому
подтверждение уходит в том же цикле — в том числе для чужих уведомлений.

`receiveTimeout` — просьба к серверу подождать, а не гарантия: шлюз GREEN-API
может ответить пустым телом мгновенно. Поэтому при пустой очереди цикл
выдерживает паузу (`MIN_POLL_INTERVAL_MS`, по умолчанию 5 секунд), иначе опрос
превращается в непрерывный поток запросов. Если уведомление пришло, следующий
запрос уходит без паузы — очередь разбирается на полной скорости. Опрос работает,
только пока открыт чат, и останавливается при выходе. Сетевые ошибки не убивают
цикл — работает экспоненциальная пауза до 30 секунд, а сверху появляется баннер.

**История берётся с сервера, а не копится в браузере.** Очередь уведомлений
одноразовая: каждое сообщение выдаётся ровно один раз. Чтобы переписка не
пропадала после перезагрузки страницы, при открытии чата подгружается
`getChatHistory`, а уведомления только дописывают новые сообщения в кэш
TanStack Query. Дубли отсекаются по `idMessage`.

**Входящие раскладываются по всем чатам, а не только по открытому.** Очередь
уведомлений общая для инстанса, поэтому опрос один на приложение: он находит
чат по `chatId` или телефону отправителя, дописывает сообщение в его ленту и
увеличивает счётчик непрочитанных, если чат сейчас не открыт. Незнакомый номер
заводит новый чат — уведомление всё равно удаляется из очереди, и без этого
сообщение пропало бы навсегда.

**История дополняет кэш, а не заменяет его.** Пока чат закрыт, в его ленту уже
могли попасть сообщения из очереди. Если бы `getChatHistory` при открытии
подменял кэш, они бы исчезли: журналы отдают свежие сообщения с задержкой.
Поэтому ответ сервера сливается с уже известными сообщениями по `idMessage`.

**Чат опознаётся по номеру телефона, а не по `chatId`.** Отправляем мы на
`<телефон>@c.us`, но MAX в уведомлениях присылает собственный числовой `chatId`.
Поэтому ключ чата — нормализованный телефон, а входящие сопоставляются по
`senderData.senderPhoneNumber`; настоящий `chatId` подставляется при первом
уведомлении и дальше используется для отправки.

**Коды ответов разбираются по смыслу.** Клиент переводит HTTP-коды GREEN-API
в типизированные ошибки, от которых зависит, стоит ли повторять запрос:

| Код | Значение | Поведение |
|---|---|---|
| 400 `starting` | инстанс перезапускается | повторяем с паузой |
| 400 прочее | неверные параметры запроса | останавливаемся |
| 401 | неверный `apiTokenInstance` | останавливаемся |
| 403 | неверный `idInstance` или адрес API | останавливаемся |
| 429 | слишком частые запросы | пауза с увеличением |
| 466 | исчерпан лимит тарифа | останавливаемся, сообщаем про тариф |
| 5xx | сбой на стороне сервиса | повторяем с паузой |

Текст ошибки всегда называет HTTP-код и тело ответа — иначе разные причины
(«лимит тарифа» и «неверный токен») выглядят в интерфейсе одинаково.

**Оптимистичная отправка.** Сообщение появляется в ленте сразу со статусом
«отправляется», после ответа API получает настоящий `idMessage`, а при ошибке
становится красным с кнопкой «Повторить».

**Хранение учётных данных.** `idInstance` и `apiTokenInstance` лежат в
`localStorage`, чтобы сессия переживала перезагрузку. В продакшене так делать
нельзя: токен даёт полный доступ к инстансу и должен оставаться на бэкенде,
который проксирует запросы к GREEN-API. Для тестового задания без серверной
части это осознанный компромисс.

## Что покрыто тестами

- нормализация телефона и построение `chatId` (`shared/lib/phone`);
- разбор уведомлений и элементов истории в модель сообщения (`entities/message`);
- валидация формы входа и сохранение сессии (`features/auth`);
- отправка сообщения, отправка по `Enter`, повтор после ошибки (`features/send-message`);
- разбор кодов ответа GREEN-API и признак «стоит ли повторять» (`shared/api/green-api`);
- диагностика настроек инстанса и включение уведомлений (`features/receive-messages`);
- слияние истории с сообщениями, пришедшими из очереди (`entities/message`);
- опрос очереди: доставка в фоновый чат со счётчиком непрочитанных, создание
  чата для незнакомого номера, отсутствие запросов без чатов и защита от
  непрерывного опроса (`features/receive-messages`).

## Ограничения

- Поддерживаются только текстовые сообщения — по условию задания.
- Групповые чаты не поддерживаются: чат создаётся по номеру телефона.
- Глубина истории ограничена тем, что отдаёт `getChatHistory` (до 5000 сообщений за 3 месяца).
